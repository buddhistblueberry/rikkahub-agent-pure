### D1 · 既有统计卡与账本口径不一致（已定性：口径问题，非代码缺陷）· 2026-10-03

- **发现**：2026-10-03 19:32，装机 debug 包（master `e394e221`）打开统计页
- **证据**：截图 2 张 → `qa-evidence/b8ab43db-….jpg`（上半）、`qa-evidence/4cc125a3-….jpg`（下半）
- **用户指认**：**首个问题 = 顶部统计卡与账本对不上**，输入 **27.6K** vs 账本 **130.9K**（≈5 倍）——「**上方的统计口径还是旧的**」
- **读数**：总对话数 1 ｜ 总消息数 2 ｜ 应用启动次数 1 ｜ 输入 Token 27.6K ｜ 输出 Token 353 ｜ 缓存节省 27.4K ｜ 缓存命中率 99% ｜ 账本（90 天）按日期 `2026-10-03` 5 次调用 130.9K（工具续跑 4×109.2K + 主回合 1×21.7K；模型 / 助手同值）｜ 编排树空态
- **定性＝口径问题（非缺陷）**：上方卡读 `message.usage`（P2-12c 侦察：`MessageNodeDAO.getTokenStats` 从 `message_node.messages` 里 `json_extract`），下方账本读 `usage_records`；P2-12c 口径① 已拍「既有卡片不动、两源窗口不同、永不相加」。
- **机制（待代码复核）**：一条 assistant 消息含多轮工具往返，`message.usage` 只留**末次**调用 ⇒ 27.6K；账本逐次入库 5 条 ⇒ 130.9K。**比值 5 ≈ 往返数** ⇒ 会话越长，「上方卡」少算越多（本例少算 ~80%）。
- **真机体感风险**：同一会话内 5 倍差，且上方文案（「输入 Token」）读起来像会话 / 总量 ⇒ 极易误判消耗。
- **处置候选（本轮不执行）**：① 既有 token 卡改接账本（统一口径）；② 保留旧卡但加「本回合 / 末次」提示文案；③ 仅文档明示口径、UI 不动。
- **次要不阻塞**：热力图今天已有活动（1 轮对话 / 5 次调用）却未见明显着色（也可能 2 条消息落在最浅档、与空白同色）⇒ 需对照实现，另记。
- **一致性附注**：账本四维内部自洽（109.2 + 21.7 = 130.9K）；`99%` 命中率与一期 T-03 结论方向一致（首请求 ≈2%、第二回合起 96~99%），暂不算异常。

### D2 · 工作区缺「默认记忆目录」与「新建文件夹」入口（非 bug · 功能 / 体验缺失）· 2026-10-03

- **发现**：2026-10-03，用户实测（无截图）
- **现象**：
  1. **工作区没有默认自动生成的记忆存储目录** —— 现 `/workspace/memory-archive/` 是 **2026-09-28 手动建的**，不是 app 预置；工作区首次打开是空目录、无任何结构。
  2. **用户无法在工作区 UI 手动创建文件夹** —— 工作区文件页没有「新建文件夹」入口。
- **影响**：记忆冷储存目录 / 项目目录只能由 **agent 工具**（`workspace_create_folder` 等）创建；用户自己在 UI 侧无法组织文件结构，也看不到「该往哪放记忆」的默认约定。
- **性质**：RikkaHub 客户端**产品能力缺失 / 体验问题**，**非二期纯化引入的缺陷**（与 §9.2「口径声明」同类：不是 bug，但需明示 / 后续补）。
- **候选**：① 工作区首次使用自动落默认结构（如 `memory/` + `projects/`）；② 文件页补「新建文件夹」（连带重命名 / 移动）。

### D3 · 无法上传音频 / 视频 ⇒ 多模态「专家团」作用受限（历史遗留 · 非二期引入）· 2026-10-03

- **发现**：2026-10-03，用户实测（**历史遗留问题**，非本次引入）
